# Demo video script (under 3:00)

The voiceover is about 400 words, roughly 2:45 at a calm pace. **[Brackets]** are what's on screen. Tell it from the store owner's point of view: someone who can't code and wants a PayPal button.

---

**0:00 to 0:15 · The problem**
[The Tidepool Goods cart page with only "Pay with card".]
> Meet Tidepool Goods. A freelancer built this store, and it only takes cards. The owner wants PayPal. Their options: pay a developer for days of work, or touch code they don't understand.

**0:15 to 0:30 · The landing page**
[paypal-checkout-integrator.onrender.com. The hero animation: the PayPal button slides in and the test card ticks to 9 of 9. Scroll slowly past "See it working in 60 seconds".]
> PayPal Checkout Integrator, by Chui Labs, adds PayPal to a custom-built store without touching code, and proves it works with real PayPal test purchases before anything changes.

**0:30 to 0:50 · Connect and start**
[Click "Start free with GitHub". On My stores, the store card shows the dashed "PayPal goes here" slot. Open the store: the four-step timeline. Click "Add PayPal checkout".]
> The owner signs in with GitHub, picks their store, and clicks one button. Each step is explained in plain English.

**0:50 to 1:15 · The plan, in plain English**
[The run page: the tracker on "Waiting for your OK". The four plan cards: what customers will see, what we'll change, what stays the same, what you'll need to do. Hover "Your card payments will not be touched". Click "Looks good, build it". Then flip the header toggle to Developer for 3 seconds to show the file plan, and flip back.]
> First, a Claude agent reads the store and writes a plan. The owner sees it in plain words: customers get a PayPal button next to the card button, and card payments stay exactly as they are. Developers can see every file. Nothing is written until the owner says yes.

**1:15 to 1:40 · The work (time-lapse; caption: "30 minutes, sped up")**
[The tracker moving through "Adding PayPal checkout" and "Testing with real test purchases", with the spinning working panel. Cut to the Developer view's live log for 2 seconds: APIMatic lookups, guards passing.]
> The agent writes the integration with PayPal's server SDK, generated by APIMatic, and looks up every SDK call in APIMatic's Context Plugin before using it. Then strict checks run: the build, and guards that make sure the card checkout wasn't touched and no secrets leaked. The AI doesn't decide whether it worked.

**1:40 to 2:05 · The proof**
[The run page ring: "9/9 tests passed" and the nine tiles appearing. Open the test report: the purchase video playing next to the "PayPal's record" receipt (COMPLETED, total charged). Scroll to Stripe and PayPal side by side.]
> A robot shopper makes nine real PayPal sandbox purchases. It cancels halfway, gets declined, tries to change the price, sends fake payment notices, and refunds. PayPal's own records decide pass or fail, and every PayPal order matches the same cart paid by card.

**2:05 to 2:20 · Accept it**
[Click "Accept the change on GitHub". PR #1: the green "PayPal checkout" check and the scenario table.]
> The owner gets the finished change on GitHub with a green check, and accepts it with one click.

**2:20 to 2:45 · It keeps watching**
[PR #3 on tidepool-store: the red "PayPal checkout" check, 7 of 9. Zoom in on the comment: "a shopper could pay one cent for a $129 order".]
> From then on, every change is re-tested. Here someone later "simplified" checkout. Real test purchases caught it: a shopper could pay one cent for a $129 blanket. The check went red with a plain explanation before anyone accepted it.

**2:45 to 3:00 · Close**
[Text card: "PayPal Checkout Integrator · Chui Labs". Below it: Claude · APIMatic · PayPal JS SDK v6 · Orders v2 · Playwright · Render. "Sandbox only. Open source."]
> PayPal Checkout Integrator. Add PayPal to your store, proven with real purchases, on every change.

## Recording checklist

- **Setup:**
  - Record in 1080p (OBS, or Win+Alt+R) with only the browser window showing, zoomed to 110%.
  - Keep the laptop plugged in with sleep turned off; the worker must stay running. The landing page should say "Test robot online now".
  - Use a private window for the landing page shots, so it shows the signed-out page.
- **Record these clips separately:**
  1. The landing page.
  2. Sign in, the store card, the store page, starting the run, and approving the plan, for a fresh run on `tidepool-goods`.
  3. The whole run, for the time-lapse.
  4. The finished run page, the report, and PR #1, in real time.
  5. PR #3's red check and comment. Keep PR #3 open and **don't merge it**.
- **Backup:** if the fresh run is slow or fails on the day, use the finished run on `tidepool-store` for clips 3 and 4. Its report and PR are already complete.
- **Edit:** in Clipchamp, speed up clip 3, add the caption and the closing card, then record the voiceover last.
